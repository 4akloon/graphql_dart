# M7d GraphQL over Server-Sent Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the fourth part of stage M7 in `typed_graphql_server`: the graphql-sse protocol (R5.8) in both of its modes, through the one entry point `GraphQLHttpHandler`. Distinct connections mode answers a `GET` or `POST` whose `Accept` prefers `text/event-stream` with an event stream of the operation's results (subscriptions included); single connection mode (opt-in, `SingleConnectionOptions`) reserves a stream with `PUT`, connects it with a token, runs operations posted to it with an `operationId` and cancels them with `DELETE`. Streams have real backpressure and keep-alive comments. It adds `GQL433`-`GQL438` to the core catalog, the hostile-input tests and the SSE guide.

**Architecture:** The new `lib/src/sse/` (dartdoc category `sse`, guide `doc/sse.md`) holds the public `SseOptions` and `SingleConnectionOptions` and the internal pieces: `EventStreamWriter` frames events, `EventStream` turns a `Stream<JsonValue>` into a `StreamedBody` whose pause, resume and cancel are the source's (so a slow client slows the operation and a client that leaves stops it), `DistinctStream` runs one request as its own stream, and the single-connection reservations, routes and operations keep the per-handler state of the second mode. `GraphQLHttpHandler` offers `text/event-stream` last in its negotiation and hands the request to the mode it belongs to; transport refusals stay JSON.

**Tech Stack:** Dart 3.13 (formatted with the 3.47.6 Flutter SDK's Dart 3.13.5), `package:test`, `package:meta`; no new dependency.

**Spec:** `docs/superpowers/specs/2026-10-16-m7-transports-design.md` (sections 4, 5, 10, 13, 14, 15 deviation 11, and 17), `docs/requirements.md` (R0.3, R5.8), the protocol `reference/graphql-sse/PROTOCOL.md` and its reference server `reference/graphql-sse/src/handler.ts`.

## Review Focus

1. Every stream is lazy (the source is listened to only when the host listens to the body), forwards pause and resume to the source, and on cancel cancels the source, so resolvers stop when the client leaves; a paused client gets no keep-alive comments.
2. Event framing matches the protocol: `event: next` with the JSON on one line, `event: complete` with an empty `data`, a `:` comment first and every `keepAliveInterval`; single connection events carry `{"id":...,"payload":...}` and `{"id":...}`.
3. Transport refusals before the pipeline stay JSON; in a distinct stream a request error is a `next` event of an accepted stream, while `405`, `500` and a CSRF `403` stay JSON (a forged request never opens a stream); a batch with an event-stream `Accept` is `406`.
4. Single connection state is bounded: `maxReservations`, `reservationTimeout` (an unconnected reservation and its held operations are dropped), `maxOperationsPerStream`; closing a stream cancels its operations and drops its reservation; tokens are 128 bits from `Random.secure`.
5. No connection header (deviation 11); the `405` `allow` header names `PUT` and `DELETE` only when single connection mode is on.

import 'dart:async';
import 'dart:convert';

import 'package:test/test.dart';
import 'package:typed_graphql/typed_graphql.dart';
import 'package:typed_graphql_server/src/sse/event_stream.dart';
import 'package:typed_graphql_server/typed_graphql_server.dart';

/// A reader of the chunks of an event stream body.
final class ChunkReader {
  ChunkReader(HttpResponseData response) {
    final body = response.body as StreamedBody;
    _subscription = body.chunks.listen(
      (chunk) => chunks.add(utf8.decode(chunk)),
    );
  }

  late final StreamSubscription<List<int>> _subscription;
  final List<String> chunks = [];

  /// Completes when the body is done.
  Future<void> get finished => _subscription.asFuture<void>();

  Future<void> cancel() => _subscription.cancel();

  void pause() => _subscription.pause();

  void resume() => _subscription.resume();
}

const Duration _tick = Duration(milliseconds: 20);

void main() {
  late StreamController<JsonValue> source;
  late bool isSourceCancelled;
  late bool isSourcePaused;

  setUp(() {
    isSourceCancelled = false;
    isSourcePaused = false;
    source = StreamController<JsonValue>(
      onCancel: () => isSourceCancelled = true,
      onPause: () => isSourcePaused = true,
      onResume: () => isSourcePaused = false,
    );
  });

  EventStream stream({bool sendsComplete = true, Duration? keepAlive}) =>
      EventStream(
        source.stream,
        keepAliveInterval: keepAlive ?? const Duration(hours: 1),
        sendsComplete: sendsComplete,
      );

  group('EventStream', () {
    test('answers 200 with the event stream headers and no connection', () {
      final response = stream().response();
      expect(response.status, 200);
      expect(response.headers, {
        'content-type': 'text/event-stream; charset=utf-8',
        'cache-control': 'no-cache',
      });
    });

    test('keeps the headers an extension added', () {
      final response = stream().response(
        extraHeaders: const {'X-Extension': 'y'},
      );
      expect(response.headers['x-extension'], 'y');
    });

    test('writes a comment before anything else', () async {
      final reader = ChunkReader(stream().response());
      await Future<void>.delayed(Duration.zero);
      expect(reader.chunks, [':\n\n']);
      await reader.cancel();
    });

    test('writes a comment every keep-alive interval while idle', () async {
      final reader = ChunkReader(stream(keepAlive: _tick).response());
      await Future<void>.delayed(_tick * 4);
      expect(reader.chunks.length, greaterThanOrEqualTo(3));
      expect(reader.chunks, everyElement(':\n\n'));
      await reader.cancel();
    });

    test('an event postpones the next keep-alive comment', () async {
      final reader = ChunkReader(
        stream(keepAlive: _tick * 3).response(),
      );
      await Future<void>.delayed(_tick * 2);
      source.add(const JsonString('x'));
      await Future<void>.delayed(_tick * 2);
      expect(reader.chunks, [':\n\n', 'event: next\ndata: "x"\n\n']);
      await reader.cancel();
    });

    test('writes the events in order and then complete', () async {
      final reader = ChunkReader(stream().response());
      source
        ..add(JsonNumber(1))
        ..add(JsonNumber(2));
      await source.close();
      await reader.finished;
      expect(reader.chunks, [
        ':\n\n',
        'event: next\ndata: 1\n\n',
        'event: next\ndata: 2\n\n',
        'event: complete\ndata:\n\n',
      ]);
    });

    test('ends without complete when it is not asked to send one', () async {
      final reader = ChunkReader(stream(sendsComplete: false).response());
      source.add(JsonNumber(1));
      await source.close();
      await reader.finished;
      expect(reader.chunks, [':\n\n', 'event: next\ndata: 1\n\n']);
    });

    test('ends without complete when the source fails', () async {
      final reader = ChunkReader(stream().response());
      source.addError(StateError('boom'));
      await reader.finished;
      expect(reader.chunks, [':\n\n']);
      expect(isSourceCancelled, isTrue);
    });

    test('cancelling the body cancels the source', () async {
      final reader = ChunkReader(stream().response());
      await Future<void>.delayed(Duration.zero);
      await reader.cancel();
      expect(isSourceCancelled, isTrue);
    });

    test('cancelling the body stops the keep-alive comments', () async {
      final reader = ChunkReader(stream(keepAlive: _tick).response());
      await Future<void>.delayed(_tick * 2);
      await reader.cancel();
      final seen = reader.chunks.length;
      await Future<void>.delayed(_tick * 3);
      expect(reader.chunks, hasLength(seen));
    });

    test('pausing the body pauses the source and resuming resumes', () async {
      final reader = ChunkReader(stream().response());
      await Future<void>.delayed(Duration.zero);
      reader.pause();
      expect(isSourcePaused, isTrue);
      reader.resume();
      expect(isSourcePaused, isFalse);
      await reader.cancel();
    });

    test('does not listen to the source before the body is listened', () {
      stream().response();
      expect(source.hasListener, isFalse);
    });
  });
}

# Server-sent events

GraphQL over server-sent events (R5.8) streams the results of a subscription,
or of any operation, as `text/event-stream`. `GraphQLHttpHandler` answers
event streams in the distinct connections mode and in the single connection
mode of the graphql-sse protocol.

This guide is written in steps. So far it holds the pieces of the event
stream itself.

## Event streams

An event stream answers `200` with `content-type: text/event-stream;
charset=utf-8` and `cache-control: no-cache`. It sends no `connection` header:
the header is hop-by-hop and forbidden in HTTP/2. The body is written as it
comes and starts with a comment (`:`), which flushes the headers through
proxies. Events are `next`, one per result, and `complete`.

`SseOptions.keepAliveInterval` (12 seconds by default) is how long a stream
may stay silent before the server writes another comment, so that proxies and
load balancers do not close an idle connection:

```dart
import 'package:typed_graphql_server/typed_graphql_server.dart';

void main() {
  const options = SseOptions(keepAliveInterval: Duration(seconds: 5));
  print(options.keepAliveInterval.inSeconds);
}
```

It prints:

```text
5
```

import 'dart:async';

import 'package:meta/meta.dart';
import 'package:typed_graphql/typed_graphql.dart';

import '../http/http_response_body.dart';
import '../http/http_response_data.dart';
import '../server/header_names.dart';
import 'event_stream_writer.dart';

/// An event stream: the `200` response that carries a stream of payloads as
/// server-sent events (spec section 10).
///
/// The body is backed by a controller whose pause, resume and cancel are the
/// source's, so a slow client slows the operation down and a client that goes
/// away stops it. The source is not listened to until the host listens to the
/// body.
@internal
final class EventStream {
  /// Creates a stream of the payloads of [source].
  ///
  /// A comment is written every [keepAliveInterval] while the stream is idle.
  /// With [sendsComplete], a `complete` event follows the last payload.
  EventStream(
    this._source, {
    required this.keepAliveInterval,
    this.sendsComplete = true,
  });

  /// The headers of an event stream. There is no `connection` header: it is
  /// hop-by-hop and forbidden in HTTP/2 (spec deviation 11).
  static const Map<String, String> headers = {
    'content-type': 'text/event-stream; charset=utf-8',
    'cache-control': 'no-cache',
  };

  final Stream<JsonValue> _source;

  /// How long the stream may stay silent before a comment is written.
  final Duration keepAliveInterval;

  /// Whether a `complete` event follows the last payload.
  final bool sendsComplete;

  static const EventStreamWriter _writer = EventStreamWriter();

  // Late so that the callbacks can be instance methods.
  late final StreamController<List<int>> _controller =
      StreamController<List<int>>(
        onListen: _start,
        onPause: _pause,
        onResume: _resume,
        onCancel: _stop,
      );

  StreamSubscription<JsonValue>? _subscription;
  Timer? _keepAlive;

  /// The `200` response, with [extraHeaders] (such as those of the pipeline's
  /// response) under the event stream's own.
  HttpResponseData response({Map<String, String> extraHeaders = const {}}) =>
      HttpResponseData(
        200,
        headers: const HeaderNames().merged(
          const HeaderNames().lowerCased(extraHeaders),
          headers,
        ),
        body: StreamedBody(_controller.stream),
      );

  // The first comment flushes the headers through proxies before any
  // operation has produced anything.
  void _start() {
    _write(_writer.comment());
    _subscription = _source.listen(
      (payload) => _write(_writer.next(payload)),
      onError: (Object _) => _finish(withComplete: false),
      onDone: () => _finish(withComplete: sendsComplete),
      cancelOnError: true,
    );
  }

  void _write(List<int> bytes) {
    if (_controller.isClosed) return;
    _controller.add(bytes);
    _keepAlive?.cancel();
    _keepAlive = Timer(keepAliveInterval, _writeKeepAlive);
  }

  // A paused client already has bytes it has not read: another comment would
  // only grow the buffer.
  void _writeKeepAlive() {
    if (_controller.isPaused) {
      _keepAlive = Timer(keepAliveInterval, _writeKeepAlive);
    } else {
      _write(_writer.comment());
    }
  }

  void _finish({required bool withComplete}) {
    _keepAlive?.cancel();
    if (withComplete) _controller.add(_writer.complete());
    _controller.close().ignore();
  }

  void _pause() => _subscription?.pause();

  void _resume() => _subscription?.resume();

  Future<void> _stop() {
    _keepAlive?.cancel();
    return _subscription?.cancel() ?? Future<void>.value();
  }
}

/// Encodes the events of GraphQL over server-sent events as UTF-8 bytes
/// (spec section 10).
@internal
final class EventStreamWriter {

  const EventStreamWriter();

  /// A `next` event carrying [payload].
  ///

  List<int> comment() => utf8.encode(':\n\n');

/// Answers one request as its own event stream, the distinct connections mode
/// of GraphQL over server-sent events (spec section 10).
@internal
final class DistinctStream<C> {
  /// Creates the mode over [server]: streams write a keep-alive comment every
  /// [keepAliveInterval] and refusals are written by [writer].
  const DistinctStream(this.server, this.keepAliveInterval, this.writer);

  /// The pipeline.
  final GraphQLServer<C> server;

  /// How long a stream may stay silent before a comment is written.
  final Duration keepAliveInterval;

  /// Writes the JSON refusals.
  final ResultWriter writer;

  /// The answer to [params], sent by [http].
  ///
  /// Every operation type is allowed, since a stream can deliver them all. A
  /// `405` and a `500` are JSON transport refusals; any other single result,
  /// a request error included, is the one `next` event of an accepted stream
  /// (protocol "Distinct connections mode"); a subscription is one `next` per
  /// result. Each stream ends with `complete`.
  Future<HttpResponseData> run(
    HttpRequestData http,
    GraphQLRequest params,
  ) async {
    final response = await server.handle(
      const PipelineRequests().of(
        http,
        params,
        allowedOperationTypes: ServerRequest.allOperationTypes,
      ),
    );
    return switch (response) {
      SingleResponse() && final single when _isRefusal(single.outcome) =>
        writer.single(single, ResponseMediaType.json),
      SingleResponse(:final payload) => _stream(
        Stream.value(payload.toJson()),
        response,
      ),
      StreamResponse(:final results) => _stream(
        results.map((result) => result.toJson()),
        response,
      ),
    };
  }

  bool _isRefusal(ServerOutcome outcome) =>
      outcome == ServerOutcome.methodNotAllowed ||
      outcome == ServerOutcome.internalError;

  HttpResponseData _stream(
    Stream<JsonValue> payloads,
    ServerResponse response,
  ) => EventStream(
    payloads,
    keepAliveInterval: keepAliveInterval,
  ).response(extraHeaders: response.headers);
}

import 'package:meta/meta.dart';

import '../http/media_range.dart';

/// Decides whether an `Accept` header allows `text/plain`, the type of a
/// reservation token (spec section 10).
@internal
final class PlainTextAccept {
  /// Creates the check.
  const PlainTextAccept();

  /// The `content-type` of the token.
  static const String contentType = 'text/plain; charset=utf-8';

  /// Whether [accept] allows `text/plain`: it is missing or blank, or the most
  /// specific range that matches it (`text/plain`, `text/*`, `*/*`) has a
  /// quality above 0.
  bool allows(String? accept) {
    if (accept == null || accept.trim().isEmpty) return true;
    var specificity = -1;
    var quality = 0.0;
    for (final element in accept.split(',')) {
      final range = MediaRange.parse(element);
      final match = range == null ? null : _specificity(range);
      if (range == null || match == null || match < specificity) continue;
      if (match > specificity) quality = 0;
      specificity = match;
      if (range.quality > quality) quality = range.quality;
    }
    return quality > 0;
  }

  // 2 for the exact type, 1 for `text/*`, 0 for `*/*`, null for no match.
  int? _specificity(MediaRange range) {
    if (range.type == '*') return 0;
    if (range.type != 'text') return null;
    if (range.subtype == '*') return 1;
    return range.subtype == 'plain' ? 2 : null;
  }
}

/// The state behind one reservation of single connection mode: the stream
/// that carries every result of the reservation (spec section 10).
@internal
final class SingleConnection {
  /// Creates a connection that calls [onClosed] once, when the stream ends or
  /// is abandoned.
  SingleConnection({required this.onClosed});

  /// Called once, when the stream ends or is abandoned.
  final void Function() onClosed;

  // Late so that the callback can be an instance method.
  late final StreamController<List<int>> _frames = StreamController<List<int>>(
    onCancel: _clientWentAway,
  );

  /// Whether a request has connected the stream.
  bool isConnected = false;

  bool _isClosed = false;

  /// Marks the stream as connected and gives its event stream, which sends a
  /// comment every [keepAliveInterval]. It never ends by itself.
  EventStream connect(Duration keepAliveInterval) {
    isConnected = true;
    return EventStream.frames(
      _frames.stream,
      keepAliveInterval: keepAliveInterval,
    );
  }

  /// Drops the reservation and ends the stream.
  void abandon() {
    if (!_close()) return;
    _frames.close().ignore();
  }

  Future<void> _clientWentAway() {
    _close();
    return Future<void>.value();
  }

  // False when the connection was closed already.
  bool _close() {
    if (_isClosed) return false;
    _isClosed = true;
    onClosed();
    return true;
  }
}

      );

import 'dart:async';
import 'dart:math';

import 'package:meta/meta.dart';

import 'connect_outcome.dart';
import 'single_connection.dart';
import 'single_connection_options.dart';

/// The reservations of single connection mode: tokens that stand for a stream
/// to come (spec section 10).
///
/// A reservation lives until its stream closes, or until
/// [SingleConnectionOptions.reservationTimeout] passes without a connection.
@internal
final class StreamReservations {
  /// Creates an empty store; connected streams send a keep-alive comment every
  /// [keepAliveInterval].
  StreamReservations(this.options, {required this.keepAliveInterval});

  /// The limits.
  final SingleConnectionOptions options;

  /// How long a connected stream may stay silent before a comment is written.
  final Duration keepAliveInterval;

  final Map<String, SingleConnection> _connections = {};
  final Map<String, Timer> _timeouts = {};

  // Secure because the token is the only defence of a stream (spec section
  // 10).
  static final Random _random = Random.secure();

  /// A new token, or null when [SingleConnectionOptions.maxReservations]
  /// reservations are held.
  String? reserve() {
    if (_connections.length >= options.maxReservations) return null;
    final token = _newToken();
    _connections[token] = SingleConnection(onClosed: () => _drop(token));
    _timeouts[token] = Timer(
      options.reservationTimeout,
      () => _connections[token]?.abandon(),
    );
    return token;
  }

  /// Connects the stream of [token].
  ConnectOutcome connect(String token) {
    final connection = _connections[token];
    if (connection == null) return const UnknownToken();
    if (connection.isConnected) return const AlreadyOpen();
    _timeouts.remove(token)?.cancel();
    return Connected(connection.connect(keepAliveInterval));
  }

  void _drop(String token) {
    _connections.remove(token);
    _timeouts.remove(token)?.cancel();
  }

  String _newToken() {
    while (true) {
      final token = [
        for (var i = 0; i < 16; i++)
          _random.nextInt(256).toRadixString(16).padLeft(2, '0'),
      ].join();
      if (!_connections.containsKey(token)) return token;
    }
  }
}

/// Reads the stream token a request of single connection mode carries.
@internal
final class StreamTokenReader {
  /// Creates the reader.
  const StreamTokenReader();

  /// The header that carries the token.
  static const String header = 'x-graphql-event-stream-token';

  /// The token of [request]: the header, else the `token` parameter. Null when
  /// there is none or it is empty.
  String? tokenOf(HttpRequestData request) {
    final fromHeader = request.header(header);
    if (fromHeader != null && fromHeader.isNotEmpty) return fromHeader;

      return value == null || value.isEmpty ? null : value;
    } on FormatException {
      return null;
    }
  }

### Task 5: feat(typed_graphql_server): run operations on single-connection streams

import 'dart:async';

import 'package:meta/meta.dart';
import 'package:typed_graphql/typed_graphql.dart';

import 'single_connection.dart';

/// One operation running on a single-connection stream.
///
/// It is admitted when its `POST` arrives, so its id is taken at once, and
/// receives its results once the pipeline has answered. Its source is not
/// listened to until the stream is, so a held subscription runs nothing.
@internal
final class StreamOperation {
  /// Creates the operation [id] of [_connection].
  StreamOperation(this.id, this._connection);

  /// The id the client gave in `extensions.operationId`.
  final String id;

  final SingleConnection _connection;
  Stream<JsonValue>? _source;
  StreamSubscription<JsonValue>? _subscription;
  bool _isCancelled = false;

  /// Gives the operation the stream of its results.
  ///
  /// An operation cancelled meanwhile (by a `DELETE` or by the stream going
  /// away) releases [source] without listening to it.
  void attach(Stream<JsonValue> source) {
    _source = source;
    if (_isCancelled) {
      _release(source);
    } else if (_connection.isListening) {
      start();
    }
  }

  /// Starts forwarding the results, if they are known and not started yet.
  void start() {
    final source = _source;
    if (source == null || _subscription != null || _isCancelled) return;
    _subscription = source.listen(
      (payload) => _connection.sendNext(this, payload),
      // A failing source ends the operation, so the client is not left
      // waiting for a result that never comes.
      onError: (Object _) => _connection.complete(this),
      onDone: () => _connection.complete(this),
      cancelOnError: true,
    );
    if (_connection.isPaused) _subscription?.pause();
  }

  /// Pauses the results while the client reads slowly.
  void pause() => _subscription?.pause();

  /// Resumes the results.
  void resume() => _subscription?.resume();

  /// Stops the operation; its resolvers are cancelled through the source.
  void cancel() {
    if (_isCancelled) return;
    _isCancelled = true;
    final subscription = _subscription;
    final source = _source;
    if (subscription != null) {
      subscription.cancel().ignore();
    } else if (source != null) {
      _release(source);
    }
  }

  // Cancelling a never-listened pipeline stream releases what it holds.
  void _release(Stream<JsonValue> source) =>
      source.listen(null).cancel().ignore();

        http,
        params,

      );

+## Single connection mode
+
+Browsers limit the connections to one origin under HTTP/1.1, so a client with
+many subscriptions can ask for one stream that carries them all. It is on when
+`SseOptions.singleConnection` holds a `SingleConnectionOptions` value:
+
+```text
+HttpOptions(
+  sse: SseOptions(singleConnection: SingleConnectionOptions()),
+)
+```
+
+The flow, with the token in the `x-graphql-event-stream-token` header or in
+the `token` query parameter:
+
+| Request | Answer |
+|---|---|
+| `PUT` | reserves a stream: `201`, `text/plain`, the token (the `Accept` header must allow `text/plain`) |
+| `GET` with the token and `Accept: text/event-stream` | connects the stream; it stays open until the client goes away and never sends `complete` for itself |
+| `POST` of a request with the token and `extensions.operationId` | starts the operation: `202` with an empty body; its events come on the stream |
+| `DELETE` with the token and `?operationId=<id>` | cancels the operation: `200`, also for an id that is not running |
+
+The events of an operation carry its id: `next` has the data
+`{"id":"a","payload":{"data":{...}}}` and `complete` has `{"id":"a"}`. An
+operation that is cancelled sends no `complete`. A result produced before the
+client connects is held and flushed on connect; a subscription is not even
+started until the stream is listened to.
+
+Refusals:
+
+| Status | Code | When |
+|---|---|---|
+| `404` | `GQL433` | no stream is reserved for the token |
+| `409` | `GQL434` | the stream for the token is already open |
+| `400` | `GQL435` | a `POST` has no `extensions.operationId` (a `DELETE` has no `operationId`) |
+| `409` | `GQL436` | an operation with that id is already running on the stream |
+| `409` | `GQL438` | the stream runs more than `maxOperationsPerStream` operations |
+| `503` | `GQL437` | the server holds `maxReservations` reservations |
+
+A batch cannot run on an event stream (`422`, `GQL428`). While the mode is on,
+a `405` lists `allow: GET, POST, PUT, DELETE`; while it is off, a token is
+ignored and `PUT` and `DELETE` are `405`.
+
+The reservations live in the handler, in memory. A deployment with several
+instances needs sticky sessions, so that the `PUT`, the `GET` and the `POST`s
+of one client reach the same instance.
+
+The token is what protects the stream: only a client that read the answer to
+the `PUT` holds it, and a cross-site `PUT` needs a preflight. The operations
+are ordinary JSON `POST`s and pass the CSRF rule of the server profile. Keep
+the token out of logs, and prefer the header to the query parameter, which
+proxies tend to log.
+

+## Proxies
+
+A proxy that buffers the response holds the events back until the buffer
+fills. Turn buffering off for the endpoint: for nginx send the response header
+`X-Accel-Buffering: no` (set it in the host, it is a proxy instruction and not
+part of the protocol) or `proxy_buffering off`, and do not compress the
+response. The host adapter must write each chunk to the socket and flush it,
+not collect the body. Under HTTP/1.1 a browser opens six connections to an
+origin, and every distinct stream takes one; that is what the single
+connection mode is for.
+
+## Limits
+
+`SingleConnectionOptions` bounds the mode:
+
+- `maxReservations` (1000): reservations held at once; more is `503`;
+- `reservationTimeout` (30 seconds): a reservation that no `GET` connects in
+  this time is dropped with the operations it held;
+- `maxOperationsPerStream` (100): operations running or held on one stream.
+
+A stream whose body the host never listens to is not dropped by the handler:
+the host must cancel or listen to every body it gets. The limits of the
+pipeline (`ServerLimits`, cost, cancellation and timeouts) apply to every
+operation as for any request.
